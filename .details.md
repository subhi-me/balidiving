## 1. Arsitektur Repositori & `.gitignore`

Repositori ini telah dibersihkan dari file-file dependensi yang berat agar proses pengembangan berjalan ringan dan cepat.

### File yang Wajib Diabaikan
File `.gitignore` di root direktori dikonfigurasi untuk mencegah folder berat seperti `node_modules` masuk ke GitHub. Jika dependensi berubah, tim cukup menjalankan `npm install` kembali di lokal masing-masing.

Isi file `.gitignore`:
```gitignore

node.js/node_modules/

# File arsip besar & Log
*.zip
*.tar.gz
*.log
en/error_log

# Environment rahasia (Credentials)

```

## 2. Sistem Otomatisasi CI/CD (GitHub Actions)

Website dikonfigurasi untuk **Otomatis Deploy** ke Hostinger setiap kali ada perubahan yang di-push ke branch utama (`main`). Kamu tidak perlu lagi mengunggah file secara manual via File Manager atau FTP desktop.

### File Konfigurasi Alur Kerja (Workflow)

Skrip otomatisasi berada di: `.github/workflows/deploy.yml`

```yaml
name: Deploy Website ke cPanel

on:
  push:
    branches:
      - main

jobs:
  web-deploy:
    name: 🎉 Deploy via FTP
    runs-on: ubuntu-latest
    steps:
    - name: 🚚 Ambil kode terbaru
      uses: actions/checkout@v4
    
    - name: 🚀 Upload file ke Hostinger
      uses: SamKirkland/FTP-Deploy-Action@v4.3.5
      with:
        server: ${{ secrets.FTP_SERVER }}
        username: ${{ secrets.FTP_USERNAME }}
        password: ${{ secrets.FTP_PASSWORD }}
        local-dir: ./
        server-dir: /public_html/  # Sesuaikan dengan target folder di Hostinger
        exclude: |
          **/.git*
          **/.git*/**
          **/node_modules/**

```

### Variabel Rahasia (GitHub Secrets)

Agar skrip di atas bekerja, variabel FTP di bawah ini **wajib** didaftarkan pada menu **Settings ➔ Secrets and variables ➔ Actions** di halaman repositori GitHub:

| Nama Secret | Deskripsi / Nilai |
| --- | --- |
| `FTP_SERVER` | Hostname FTP dari Hostinger (cth: `ftp.subhi.me` atau alamat IP) |
| `FTP_USERNAME` | Username FTP Akun Hostinger |
| `FTP_PASSWORD` | Password FTP Akun Hostinger (Jika lupa, reset di hPanel Hostinger) |

## 3. Kebijakan Keamanan & Autentikasi Git (PENTING)

GitHub menerapkan proteksi ketat saat mendeteksi pembuatan atau pembaruan file di dalam folder `.github/workflows/`. Aplikasi terminal (PowerShell/CMD) tidak diizinkan melakukan push skrip otomatisasi kecuali menggunakan **Personal Access Token (PAT)** yang memiliki hak akses khusus.

### Solusi Masalah Izin (Scope Workflow Error)

Jika saat melakukan push muncul error `refusing to allow an OAuth App to create or update workflow... without workflow scope`, ikuti langkah ini:

1. Buka GitHub **Settings ➔ Developer settings ➔ Personal access tokens (classic)**.
2. Buat token baru (*Generate new token*).
3. **Wajib centang** opsi scope: `repo` dan **`workflow`**.
4. Gunakan kode token yang dihasilkan (`ghp_...`) sebagai **password** saat melakukan operasi Git di terminal.

### Format Push Tembak Langsung (Bypass Windows Cache)

Jika Windows Credential Manager menyimpan sesi login OAuth lama yang tidak punya izin, gunakan perintah push langsung dengan menyisipkan token:

```powershell
git push https://<KODE_TOKEN_PAT_KAMU>@[github.com/subhi-me/balidiving.git](https://github.com/subhi-me/balidiving.git) main

```

## 4. Alur Kerja Harian untuk Developer

Bagi tim developer yang melanjutkan pengerjaan proyek ini, berikut alur kerja standarnya:

1. Lakukan perubahan kode di lokal komputer.
2. Tarik file ke antrean Git:

```powershell
   git add .

```

3. Lakukan commit dengan pesan yang jelas:

```powershell
   git commit -m "Fitur: Menambahkan halaman artikel baru Bali Diving"

```

4. Kirim ke GitHub (dan otomatis ter-deploy ke server produksi):

```powershell
   git push origin main

```

5. Pantau status pengiriman di tab **Actions** pada halaman repositori GitHub untuk memastikan indikator berubah menjadi centang hijau (Success).
